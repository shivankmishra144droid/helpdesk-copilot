# Helpdesk Copilot

An AI-assisted console for call-centre agents who support a B2B marketplace. An agent types what the caller says; the copilot finds the matching known issue, walks the agent through the fix one verified step at a time, and escalates cleanly when a step is blocked. Questions the knowledge base can't answer go to a supervisor queue, where a drafted resolution can be reviewed, edited and published back into search immediately.

The demo runs on **synthetic data** for a fictional portal, *Northwind Marketplace*: 66 support issues (36 seller, 30 buyer) across 22 categories, a small help-centre FAQ, and a 198-query benchmark. Every record is generated by [`scripts/generate_demo_data.py`](scripts/generate_demo_data.py) from hand-written content in [`scripts/demo_content.py`](scripts/demo_content.py).

## What it does

**Agent console** (`http://localhost:3000`)
- Natural-language search over the seller or buyer knowledge base, with typo correction and synonym expansion.
- Off-topic queries are caught before search ("what's the weather") and the agent gets suggestions instead.
- Step-by-step guided resolution: mark each step done or blocked; blocked steps escalate to the owning team with the documents to collect.
- Browse by category when the caller can't describe the problem.
- One click sends an unanswered question to the supervisor queue.

**Supervisor workspace** (`/supervisor`)
- Queue of escalated questions, grouped into topic clusters.
- Each item arrives with a drafted resolution (from the closest KB issue or FAQ, or from an LLM if one is configured) and similar existing issues.
- Edit, approve (the answer becomes searchable at once), or reject; batch actions and an audit trail.
- Category management and an analytics dashboard.

## How search works

```
query ─► normalise & spell-correct ─► intent / category prediction ─► off-topic gate
      ─► FAISS semantic search + keyword scoring (hybrid) ─► optional reranker ─► results
```

| Stage | Implementation |
|---|---|
| Spell correction | Domain vocabulary built from the KB + RapidFuzz; common English words are never "corrected" |
| Intent | Logistic regression over sentence embeddings (falls back to category prototypes) |
| Off-topic gate | IsolationForest over KB embeddings plus a similarity floor |
| Retrieval | `all-MiniLM-L6-v2` embeddings in FAISS, combined with keyword and title-match scores |
| Reranking (opt-in) | XGBoost learning-to-rank or an MS MARCO cross-encoder |
| Drafting (optional) | Claude, OpenAI or a local Ollama model, few-shot from approved resolutions |

### Benchmark

From [`benchmarks/results.md`](benchmarks/results.md) (198 queries; hand-written caller phrasings, never the issue title, plus a typo variant per issue):

| Ranking mode | Top-1 | Top-3 | MRR | Median latency |
|---|---:|---:|---:|---:|
| **hybrid (default)** | 86.4% | 100.0% | 0.925 | 39 ms |
| xgboost | 84.8% | 95.5% | 0.902 | 66 ms |
| cross_encoder | 93.4% | 98.5% | 0.962 | 278 ms |

Hybrid is the default: it put the right answer in the top three for every benchmark query, at a fraction of the cross-encoder's latency. Set `RERANKING_MODE=cross_encoder` (and `CROSS_ENCODER_ENABLED=true`) when top-1 accuracy matters more than speed. Numbers come from synthetic data on one CPU, so compare modes with each other rather than reading them as absolute accuracy.

## Quick start

### Windows, one click
Double-click `run.bat`. On first run it installs Python and Node.js if missing (via winget), installs dependencies, starts both services and opens a menu. `stop.bat` stops them.

### Docker
```bash
docker compose up --build
```
Then open http://localhost:3000. Both ports are bound to `127.0.0.1` only. Approvals and the queue persist in the `knowledge` volume.

### Public demo
The root `Dockerfile` packages everything into one container for a free Hugging Face Space, running in a demo mode that blocks uploads and destructive actions. See [DEPLOY.md](DEPLOY.md).

### Manual
```bash
py -3 -m pip install -r backend/requirements.txt
py -3 scripts/train_all.py      # once: trained models are not committed (~5 min)
cd backend && py -3 -m uvicorn main:app --host 127.0.0.1 --port 8000
```
In a second terminal:
```bash
cd frontend && npm ci && npm run dev
```

To fill the supervisor queue with a few demo questions:
```bash
py -3 scripts/seed_demo_queue.py
```

## Configuration

Copy `.env.example` to `.env`. Everything is optional; with no AI provider the app drafts from KB templates.

| Variable | Purpose |
|---|---|
| `LLM_PROVIDER` | `auto` (default), `anthropic`, `openai`, `ollama` or `none` |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | Claude drafting (default model `claude-opus-5-5`) |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | OpenAI drafting (both required) |
| `OLLAMA_URL`, `OLLAMA_MODEL` | Local Ollama drafting |
| `RERANKING_MODE` | `hybrid` (default), `xgboost`, `cross_encoder`, `disabled` |
| `COPILOT_API_TOKEN` | Require a shared token on write requests |
| `DEMO_MODE` | `true` blocks uploads, re-imports and destructive category changes (public demo) |
| `NEXT_PUBLIC_API_BASE` | Backend URL for the frontend (default `http://localhost:8000`) |

With `LLM_PROVIDER=auto`, Claude is used when `ANTHROPIC_API_KEY` is set, otherwise OpenAI, otherwise a reachable Ollama. Claude requests opt into server-side refusal fallbacks. `/health` reports the active provider, model and why it is unavailable if it is.

Every write request must carry an `X-Copilot-Client` header (the frontend adds it). That forces a CORS preflight, so other websites can't submit forms to the local API.

## Regenerating data and models

```bash
py -3 scripts/generate_demo_data.py         # knowledge base, FAQ, taxonomy, benchmark queries
py -3 scripts/build_domain_dictionary.py    # spell-correction vocabulary
cd backend
py -3 ../scripts/train_intent_classifier.py
py -3 ../scripts/train_outlier.py
py -3 ../scripts/train_ranker.py
cd ..
py -3 benchmarks/run_benchmark.py           # rewrites benchmarks/results.md
```

Model files record the library versions they were trained with; `/health` → `ml.model_files` warns if the installed versions differ.

## Tests

```bash
py -3 -m pip install -r backend/requirements-dev.txt
cd backend && py -3 -m pytest -q
```

73 backend tests cover the ML components, query correction, the embedding cache, model-file loading, the Claude/OpenAI request paths (against a local stub server), and HTTP behaviour (request guard, CORS, status codes). CI (`.github/workflows/ci.yml`) also checks that committed data matches the generator and that the frontend type-checks and builds.

## Project layout

```

  main.py           agent endpoints (search, steps, ingest, health)
  supervisor.py     supervisor queue, approvals, categories, analytics
  kb_search.py      search pipeline
  llm_provider.py   Claude / OpenAI / Ollama behind one complete() call

  models/           trained models (generated)

  app/supervisor/   supervisor workspace

```

## Limitations

- No user accounts or roles; the API is meant to run on localhost.
- JSON-file storage with an in-process lock: run a single backend worker.
- The agent page (`frontend/app/page.tsx`) is still one large component.
- Benchmarks use synthetic queries written alongside the data, so they flatter real-world accuracy.
